Glossary

AI is useful in testing when we design the work around evidence and human judgment. Use these 48 entries to revisit the terms used throughout the tutorial.

Definitions and examples from the tutorial glossary. Provider labels and implementations may differ; the loop descriptions are teaching summaries.

AI and workflow concepts

LLM

A model that predicts useful continuations of text; it does not inherently know your product’s truth.

Testing exampleSuggests risks from a user story.

Kitchen analogy

A very well-read kitchen assistant who can suggest recipes and techniques, but has not tasted your dish or checked what ingredients are actually in stock.

Context

The relevant background, facts, constraints, and history supplied to help the LLM or workflow make a useful decision.

Testing exampleThe user story, acceptance criteria, known defects, supported browsers, and recent CI history.

Kitchen analogy

The order ticket, guest allergies, available ingredients, equipment, and what has already been prepared.

Prompt

One instruction or request.

Testing example“Generate tests for password reset.”

Kitchen analogy

“Make me a pasta dish.”

Instruction

A standing rule that guides behaviour across a task or workflow, rather than a single request. It defines roles, constraints, priorities, and boundaries.

Testing example“Treat CI logs as evidence; separate facts from hypotheses; never create a defect without human approval.”

Kitchen analogy

The kitchen’s standing rules: follow food-safety practices, label allergens, keep the work surface clean, and ask the head chef before serving a special order.

Structured prompt

A prompt with context, boundaries, expected format, and review criteria.

Testing exampleInclude the story, known rules, exclusions, risks, and require assumptions and evidence.

Kitchen analogy

“Make a vegetarian pasta for four in 30 minutes, using these ingredients; avoid nuts; list assumptions and give measurements.”

Skill

A reusable, task-specific capability: instructions, knowledge, and sometimes tools or procedures that help a person or AI perform a defined kind of work well.

Testing exampleA reusable guide for reviewing test automation, investigating flaky tests, or designing risk-based tests.

Kitchen analogy

A tested technique or recipe module, such as making a béchamel sauce: it specifies the purpose, ingredients, method, quality checks, and when to use it.

Hook

An event-driven trigger or callback: when a defined event occurs, it automatically runs a specific check or action. A hook does not decide whether to run; the event activates it.

Testing exampleWhen a CI run fails, automatically collect the log and test-result metadata; before a tool writes a defect, request approval.

Kitchen analogy

A kitchen timer that rings when baking ends, or an automatic hygiene check that must occur before a dish can leave the pass.

Prompt chain

Several intentional LLM steps where each output feeds the next.

Testing exampleRequirements → ambiguities → risks → tests → priorities → automation candidates → expert review.

Kitchen analogy

Decide the menu → check allergies and ingredients → choose a recipe → prepare → plate → taste and adjust.

Workflow

Work organized through predefined steps, inputs, outputs, and rules; it can include branches and loops. It may use AI but does not need to.

Testing exampleCI-failure triage with predefined conditional branches.

Kitchen analogy

A recipe that includes “if too thick, add water and check again.”

State

The recorded situation of a workflow at a point in time: known facts, completed steps, intermediate results, and unresolved questions.

Testing exampleThe failing test name, log excerpts already examined, hypotheses considered, and pending next step.

Kitchen analogy

The current status of the meal: vegetables chopped, sauce simmering, pasta not yet cooked, and an allergy question still unanswered.

Observation

New information gathered from an allowed source that can update the workflow’s state.

Testing exampleA log message, a changed file, a test-history trend, or a result from a rerun.

Kitchen analogy

Tasting the sauce, seeing that the oven has reached temperature, or learning that an ingredient is unavailable.

Feedback

Information about the result of an action that helps a workflow, person, or agent decide whether to continue, adjust, retry, escalate, or stop.

Testing exampleA rerun result, a reviewer’s correction, or confirmation that a proposed root cause was wrong.

Kitchen analogy

Tasting the adjusted sauce and deciding whether it now meets the standard or needs another change.

Action

An operation proposed or performed to move work forward. A proposed action still needs permission and validity checks before execution.

Testing examplePropose retrieving a log or rerunning a test; execute only within the authorized scope.

Kitchen analogy

Suggest using the oven; check permission and suitability before switching it on.

Tool use

Calling an external capability to retrieve facts or act.

Testing exampleRead CI logs, query test results, create a defect draft.

Kitchen analogy

Use a pantry inventory, scale, oven, blender, or a delivery order—each tool retrieves information or changes something.

Evidence

Information from approved sources that supports or weakens a claim, hypothesis, or decision.

Testing exampleA timestamped CI log, test-result history, deployment record, or reproducible test run.

Kitchen analogy

The measured temperature, tasting result, labelled ingredient list, and order ticket—not a guess about what is in the dish.

Guardrail

A check or control intended to detect or constrain unwanted behavior. Distinguish automatic validation from instructions, permission boundaries, and human approval; none guarantees correctness on its own.

Testing exampleValidate tool arguments/results, block disallowed operations, or stop at a configured limit.

Kitchen analogy

An allergen check or equipment interlock; a written reminder alone is not an interlock.

Human-in-the-loop / Expert-in-the-loop

A defined point where a person reviews, approves, corrects, or takes over a workflow decision or action. “Expert-in-the-loop” is the more specific term when that person needs relevant domain expertise, such as testing, product, security, or clinical knowledge.

Testing exampleA tester approves a rerun, defect creation, or recommendation to change automation.

Kitchen analogy

The head chef tastes and approves a special-order dish before it is served.

Stopping condition

An explicit rule for when a workflow or loop completes, escalates, or stops trying.

Testing exampleStop after supported evidence identifies a likely cause; escalate when evidence conflicts or three attempts fail.

Kitchen analogy

Serve when the dish meets the standard; ask the head chef when it does not; stop adjusting after the allowed tasting attempts.

Agency

The ability to choose and initiate a next action in pursuit of a goal, within the permissions and controls provided. Agency can be tightly bounded; it does not require unlimited independence.

Testing exampleThe system selects whether to inspect a log, compare commits, or ask the tester for more evidence.

Kitchen analogy

A sous-chef chooses whether to taste the sauce, check the pantry, or ask the head chef before continuing.

Autonomy

The degree to which a system can act without requesting human approval. Autonomy should be deliberately limited according to risk.

Testing exampleA read-only triage assistant has low autonomy; an agent that reruns tests or files defects has more.

Kitchen analogy

A trainee who must ask before every action has low autonomy; a sous-chef trusted to prepare a standard dish has more.

Harness

The surrounding setup that supplies inputs, invokes actions, captures outputs, and applies controls consistently.

Testing exampleProvides approved evidence, permitted tools, logging, limits, and approval gates for an AI workflow.

Kitchen analogy

The equipped kitchen and its rules: labelled ingredients, approved equipment, timers, hygiene checks, order tickets, and a head chef’s approval for serving.

Agent

An LLM-directed system that chooses what to do next within bounded tools, instructions, and guardrails.

Testing exampleIt decides whether to inspect logs, compare recent changes, or ask for human review.

Kitchen analogy

A sous-chef who can decide whether to taste the sauce, check the pantry, use the oven, or ask the head chef—but only within the kitchen’s rules.

Agentic loop

Repeated model-guided decisions, tool use, and feedback, ending at a stopping condition. Observe → decide → act → evaluate is our teaching summary; implementations may combine phases.

Testing exampleInspect failure → form hypothesis → collect evidence → revise → escalate or conclude.

Kitchen analogy

Taste → decide → adjust → taste again; serve, ask the chef, or stop at the limit.

Evaluation

The systematic check of whether an output or workflow was useful, accurate, safe, and efficient enough for its purpose.

Testing exampleCompare triage conclusions with confirmed root causes; measure unsupported claims, time saved, and appropriate escalations.

Kitchen analogy

Judge whether the dish meets its recipe, safety, taste, presentation, and service-time standards.

Tools, controls, and handoffs

Tool call / tool execution / tool result

A requested operation and its inputs; executing that request; the returned output. Keep these distinct. The output is an observation to inspect before using it as evidence for a claim.

Permissions and approval

Permissions define allowed operations/scope; approval authorizes a particular action when required. A recommendation or model request does not authorize itself.

Workflow state / memory

State is the current task record. Memory can also refer to information retained across tasks or sessions. Exercise 6-B's “evidence ledger” is task state held in the page until reset/reload, not persistent memory.

Orchestration / control flow

Coordination of model steps, tools, conditions, and continuation/ending decisions. “Wire the decisions” was a workshop metaphor; the page now calls this configuring the agentic loop.

Human review / agent handoff

Human review asks a person to inspect, approve, correct, or take over. An SDK agent handoff can instead transfer work to another agent. Our final block requests human review, not another AI agent.

Action budget / tool-call limit

A local limit on dispatched tool attempts. It is not interchangeable with a token budget, model-turn limit, or total loop iterations.

Decision trace

A review record of observations, actions, results, checks, and endings. It is not a transcript of hidden model reasoning or proof that a rationale is correct.

Testing concepts

Risk-based test design

Choosing test coverage and depth according to the likelihood and impact of product failures, while making uncertainty explicit.

Testing examplePrioritize reset-link reuse and invalidated credentials using the supplied product risks.

Kitchen analogy

Check the steps with the greatest food-safety consequences before minor presentation details.

Test prioritization

Ordering testing work using an explicit rationale, including risk, dependencies, and available effort.

Testing exampleExplain why credential invalidation should be checked before a cosmetic message variation.

Kitchen analogy

Decide which preparation and safety checks must happen first.

Automation candidate

A test idea considered for automation after evaluating its value, repeatability, observable result, data needs, and maintenance cost.

Testing exampleA repeatable link-reuse check may be suitable; exploratory usability assessment may remain human-led.

Kitchen analogy

Decide which repeatable preparation step suits a machine and which needs a chef’s judgment.

Over-generated tests

A volume of tests that includes unnecessary duplication, unsupported variations, or low-value cases without a clear coverage rationale.

Testing exampleSeveral differently worded tests exercise the same registered-email reset path.

Kitchen analogy

Prepare multiple identical dishes while overlooking an allergy-specific order.

Test oracle

The source or rule used to determine whether observed behaviour is correct.

Testing exampleApproved acceptance criteria establish that an already-used reset link must be rejected.

Kitchen analogy

The agreed recipe and safety standard used to judge the dish.

Weak assertion

A check that can pass without establishing the behaviour the test intends to verify.

Testing exampleChecking that a confirmation element exists does not establish that the old password no longer works.

Kitchen analogy

Confirm that a plate exists without checking that it contains the correct dish.

Brittle automation

Automation that fails because of incidental timing, implementation, or environment changes rather than a meaningful product defect.

Testing exampleA fixed one-second wait fails when a valid response takes longer.

Kitchen analogy

Assume cooking always finishes in one minute instead of checking readiness.

Automation review

A structured assessment of whether a test checks the intended behaviour reliably and maintainably.

Testing exampleReview assertions, waiting conditions, data setup, cleanup, and requirement traceability.

Kitchen analogy

Review a recipe’s ingredients, timings, checks, and repeatability before service.

CI failure triage

Initial classification of a failed pipeline run and selection of the next investigation, without prematurely declaring a root cause.

Testing exampleDistinguish possible product, test, environment, and data issues using logs and recent changes.

Kitchen analogy

Identify whether a delayed order stems from preparation, equipment, ingredients, or the order ticket.

Flaky test

A test that produces inconsistent outcomes under apparently equivalent conditions; investigation is needed to explain the variation.

Testing exampleThe same test alternates between passing and failing because its fixed delay races the response.

Kitchen analogy

A recipe produces inconsistent results because readiness depends on more than the stated cooking time.

False confidence

Treating plausible output, a passing test, or a high score as stronger evidence than it actually provides.

Testing exampleAccepting 100/100 simulator feedback as proof that the generated tests are complete.

Kitchen analogy

Assuming an attractive dish must also be correctly cooked and safe.

Workflow template

A reusable pattern for a particular type of testing work, with inputs, steps, outputs, and review criteria.

Testing exampleAdapt the automation-review template to another feature.

Kitchen analogy

Reuse a tested recipe while adjusting ingredients and checks for the order.

Workflow canvas

A compact worksheet for designing a workflow in a specific context, including evidence, permissions, review, and stopping rules.

Testing exampleDesign a bounded CI-triage workflow for the participant’s own team.

Kitchen analogy

Plan the order, ingredients, responsibilities, quality checks, and serving criteria before cooking.

Claims and uncertainty

Unsupported claim

an answer not grounded in available evidence.

Confabulation

a confident but false or inconsistent output.

Assumption

missing information explicitly declared by the system or user.

Inference

a tentative conclusion drawn from supplied evidence.
