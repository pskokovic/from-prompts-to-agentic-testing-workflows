How to use this without JavaScript

  1. Cut or mark the three task cards. Use the default order or choose any other order. Current source cards remain available at every task; each later task receives the exact reviewed previous response.
  2. For each chosen task, mark one block for each prompt part. Read the assembled prompt and copy the exact received input from the previous reviewed card.
  3. Before seeing its response, open prepared response cards. Use the numbered construction rules to reveal one response for your blocks and actual inherited text. Do not choose among outputs.
  4. Optionally write a brief review note for your record. Pass the exact response, revise and rerun, or hold. The note does not alter the next prepared response. If you revise upstream, mark all later work “Needs review” and revisit the first affected stage.

Use the worked feedback only after an attempt. The source cards below are the only initial evidence.

Initial source cards

  • REQ-01 A registered user can request a password-reset link using their email address.
  • AC-01 For a registered email, send a reset link.
  • AC-02 · Release v1 The link expires 30 minutes after issue.
  • AC-03 A successfully used link cannot be used again.
  • AC-04 After a successful reset, the new password works and the old password does not.

Known gaps: Unregistered-email behaviour; password composition/length; rate limits; the exact 30-minute boundary; multiple outstanding links; session invalidation; delivery-time guarantees.

Extract supported behaviour and gaps

Input

□ current — Use REQ-01 and AC-01–04 as current requirements; list the known gaps separately.
□ suggestion — Use the current requirements and assume a 12-character minimum is approved.

Task

□ separate — Extract supported behaviours; separate open questions from expected results.
□ complete — Complete the specification by filling in unspecified policy details.

Output format

□ linked — Return a source-linked list of behaviours and open gaps.
□ table — Return a compact table of behaviours and gaps without source IDs.

Review condition

□ grounding — Check each expected result against its source; flag unsupported claims and omissions before handoff.
□ readable — Check that the summary reads smoothly before handoff.

Identify risks

Input

□ handoff — Use current source cards and any reviewed handoff below; retain citations and open gaps.
□ shortcut — Treat the supplied input as complete policy; skip open gaps.

Task

□ impact — Identify plausible credential-protection risks; distinguish impact from unknown likelihood.
□ likelihood — Rank risks by measured likelihood from the supplied material.

Output format

□ linked — Return a source-linked list of risks, impacts, and uncertainty.
□ table — Return a compact risk table without source IDs.

Review condition

□ grounding — Check inherited claims and whether any likelihood is actually measured.
□ readable — Check that the list sounds decisive before handoff.

Propose test ideas and observable oracles

Input

□ handoff — Use current source cards and any reviewed handoff below; retain links and uncertainty.
□ shortcut — Treat the supplied input as fully confirmed policy.

Task

□ oracles — Propose up to three test ideas, including both AC-04 credential outcomes where supported.
□ confirmation — Treat a reset confirmation as sufficient evidence of credential protection.

Output format

□ linked — Return a source-linked list of test ideas and observable oracles.
□ table — Return a compact test-idea table without source IDs.

Review condition

□ grounding — Check every oracle against sources and confirm both new- and old-password outcomes.
□ readable — Check that the proposal is concise before handoff.
