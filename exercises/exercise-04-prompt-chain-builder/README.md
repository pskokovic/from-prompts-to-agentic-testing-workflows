# Exercise 4 — Prompt Chain Builder

Selected for the existing 11:49–12:05 Exercise 4 slot and linked from Testing Lab. **Implemented locally and model-checked on 27 September 2026; sampled browser interaction passed, while timed learner/facilitator, offline-package, broader browser, and delivery acceptance remain pending.** The former compact six-stage Exercise 4 is preserved in `../archive-02/exercise-04-prompt-chain/`; its checks are historical and do not validate this activity.

Open `index.html` directly with the complete tutorial directory, including `shared/`. The task map starts in the supported extraction → risks → test-ideas order, so learners can continue immediately. They may instead drag task cards or use the small up/down controls to choose **any** order. Each task uses a two-choice radio group for Input / Task / Output format / Review condition; all four start unselected. The visible prompt preview updates on every click and puts the four chosen parts above the longer supplied context. Run becomes available when all parts are chosen. Changing a choice and clicking **Run prepared response** creates another numbered run without resetting; a collapsed comparison shows the previous response. The two output-format choices produce a semantic source-linked list or a compact table without source IDs. The copyable handoff contains the corresponding plain-text bullets or Markdown table, so the next task receives exactly what was reviewed. After a run, the learner reviews it and either holds or passes its exact text. A visible **Continue to Stage 2/3** button makes progression explicit. The current source cards remain available for every task, while each task after the first receives the exact reviewed previous response. A changed upstream prompt preserves history and the first attempt and marks later stages **Needs review**.

The blocks intentionally vary source scope, task, output traceability, and review quality. Source IDs attached to a prepared response do not validate its claims. An unsupported 12-character rule, omitted old-password outcome, invented likelihood, confirmation-only oracle, or omitted source links can pass through if the learner elects to pass. The review note is optional and kept for the record and discussion; it does not change the next prepared response. The explicit pass/hold decision controls the handoff. The feedback names these limits; it does not grade the meaning of free-text notes. All six task orders run; if extraction occurs late, its response identifies that the earlier work may have relied on unextracted requirements. A final chain ending in risks or extraction is labeled accordingly rather than presented as a completed test proposal.

The first complete three-stage chain is saved as the comparison baseline. For the live checkpoint, change Stage 1, run and review it, then rerun and review Stage 2 against the new handoff. The page shows the first and revised Stage 2 responses side by side and lets the learner record which handoff is more defensible, or that neither/no clear advantage applies. Stage 3 remains **Needs review** until revisited, so the revised final output is not shown as current. Completing Stage 3 produces a side-by-side final-output comparison; this is optional take-home continuation. No automatic score selects a winner. The worksheet and worked feedback use the same checkpoint/full-comparison distinction.

`model.js` holds the source cards, blocks, prepared response rules, state, review gate, handoff, revision logic, feedback, and record. `app.js` renders sortable task cards, radio choices, explicit stage continuation, prepared runs, and copy/reset. `build-pages.cjs` generates `worksheet.html`, `response-cards.html`, and `worked-example.html` from the model and authored offline response rules. The script-free route supports any task order with block and response-construction cards. Worked feedback is a separate page. No AI service, application action, or tests execute; the page stores no state.
