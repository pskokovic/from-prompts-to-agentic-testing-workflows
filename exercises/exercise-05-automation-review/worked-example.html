EXERCISE 5 · AUTOMATION REVIEW
Local simulation · No AI service connected · Nothing is sent or saved

Proposal review:
- Synchronization · proposal lines 02–04: Retain the success/error wait with the deadline measured from submission. [TIM-01 / CODE-01]
- Credential checks · proposal lines 05–06: Revise: check each password independently in a fresh unauthenticated session. [AC-04 / DATA-01]
- Password policy · proposal line 07: Defer the policy test and request an approved policy; continue supported reset checks. [Current ACs / DATA-01]
Source-based explanation: TIM-01 supports the submission deadline; AC-04 and DATA-01 require independent fresh-session checks. No approved source defines a length rule.

Validation plan · not executed:
- Delayed valid success: Pass after both credential checks; retain submission, confirmation, and authentication observations. [TIM-01 / AC-04 / DATA-01]
- Missing or late confirmation: Fail at the submission deadline; retain submission/confirmation times and diagnostics. [TIM-01]
- Old password still works: Fail the old-password rejection assertion; retain the fresh-session authentication result. [AC-04 / DATA-01]
Outstanding checks for later acceptance: Explicit reset error; New password fails; actual results, fixture/session evidence, diagnostics, and policy clarification remain.

Assigned authority card: A
Requested action: Apply the reviewed change to a test-only branch. Do not run it, merge it, or access production.
Approval record: The designated automation reviewer approved applying this reviewed change to that test-only branch only.
Decision: Allow the requested action in this simulation
Reason: The designated reviewer approved this test-branch patch only. Validation, merge, and production remain separate.
Technical status: Proposal ready for expert review; validation still required
Authority status: ALLOWED IN SIMULATION · The named action has matching scope and a review-ready proposal. Nothing is applied or run.
Accepted after validation: No; no checks executed.
Why this is defensible and what remains open

ALLOWED IN SIMULATION · The named action has matching scope and a review-ready proposal. Nothing is applied or run.

Synchronization · proposal lines 02–04 [TIM-01 / CODE-01]: TIM-01 supports an observable bounded wait from submission. It can avoid CODE-01’s one-second snapshot race without extending the contract. The implementation still needs validation.

Credential checks · proposal lines 05–06 [AC-04 / DATA-01]: AC-04 requires both outcomes; DATA-01 requires fresh unauthenticated sessions. Carried signed-in state can hide whether the old credential still works.

Password policy · proposal line 07 [Current ACs / DATA-01]: No supplied source defines a length threshold. Deferral keeps the policy question visible without making an invented oracle authoritative.

Delayed valid success: Two seconds is within TIM-01’s submission-based limit. The full test passes only when both AC-04 credential outcomes hold.

Missing or late confirmation: This tests the documented bound and keeps a late or missing result visible.

Old password still works: This detects the credential-protection fault even when the new password works.
