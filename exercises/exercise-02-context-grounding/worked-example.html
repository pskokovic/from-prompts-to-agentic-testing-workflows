EXERCISE 02 / PREPARED EXAMPLE / V1.0

One defensible package

Review after making your first decisions. This is authored fictional teaching material, not a real model response or proof of participant competence. Equivalent justified answers are acceptable.

Included evidence

REQ-01: A registered user can request a password-reset link using their email address.

  • AC-01: For a registered email, send a reset link.
  • AC-02: The link expires 30 minutes after issue.
  • AC-03: A successfully used link cannot be used again.
  • AC-04: After a successful reset, the new password works and the old password does not.

Authority: product owner, current functional baseline v1. These sources define the requested behaviour and expected results.

Other source decisions

  • OLD-01 — exclude: superseded release v0. It conflicts with the current expiry rule. Alternatively, retain it explicitly as history, never as a second expected result.
  • TIM-01 — defer: a valid integration timing contract for later synchronization review; unnecessary for this minimal functional package. A scoped inclusion can be justified if its purpose is explained.
  • CI-01 — defer: a failed snapshot belongs in later failure investigation; observations cannot define requirements.
  • NOISE-01 — exclude: the export issue concerns a different feature.
  • SUGGEST-01 — exclude: no approved source supports a 12-character rule. Raise password policy for clarification.

Conflict and questions

Current AC-02 supersedes OLD-01: expiry is 30 minutes, not 15. No source settles the exact behaviour at precisely 30 minutes.

  1. What response and observable behaviour are required for an unregistered email?
  2. Is a token accepted or rejected at exactly 30 minutes, and how is that boundary measured?

Other valid gaps include password composition/length, multiple outstanding links, rate limits, session invalidation, and delivery-time guarantees.

Prepared test-design excerpt

  • Request using a registered email → send a reset link. [REQ-01, AC-01]
  • Use an unused token at 31 minutes → reject it as expired. [AC-02]
  • Reuse a successfully used link → reject reuse. [AC-03]
  • After a successful reset, check authentication in fresh sessions → new password succeeds and old password fails. [AC-04]

These are representative conditions, not a complete test suite. Exact-boundary and password-policy oracles remain pending clarification.

Compare with a weak package

A package that treats OLD-01 as an active rule alongside AC-02 offers incompatible expiry expectations. Including the AI suggestion risks turning a plausible policy into an unsupported oracle. Adding an export issue does not repair missing reset requirements. More context alone does not improve the evidence.

Facilitator and self-review guidance

Ask participants to explain their first choices before revealing this example. Review authority, relevance, conflict handling, and visible uncertainty. Do not require identical source counts or wording.

Challenge: “What would justify including that source here?” A historical source can document a resolved conflict; the timing contract can be useful with an explicit scope. Ask for reasoning, not keyword matching.

Allow one revision in the timebox. Ask which evidence changed the decision and which questions remain. The interactive simulator checks structured selections and completion only; it does not understand or grade the written explanations.

Transition: even well-selected evidence may not support a confident causal claim. Exercise 3 asks what the observations actually establish.
